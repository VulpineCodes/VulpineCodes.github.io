Sy-Reality!

A karaoke stage, inside a headset.

Sy-Reality! is a VR karaoke experience for Meta Quest 3. Pick a song, step onto a virtual stage, and perform while a lyric-sync engine drives every cue. Songs are data, not hard-coded scenes, so the timing core can be tested to the millisecond without putting on the headset.

Why it exists

At the Wallace Lab I built VR for neuroscience: precise, controlled, deliberately unfun. Sy-Reality! points the same real-time skills at the opposite goal. Karaoke is nerves and joy and a room full of people who love you. A headset can give anyone the stage.

The name nods to my SyBBURE fellowship, where the project started. The timing engine is tested and deterministic. The in-headset experience is in active development on real Quest 3 hardware.

My role: Solo project. Unity and C#, interaction design, the lyric-sync engine, environment direction.

Engineering decisions and trade-offs

Songs as data, not scenes

Each song is a definition: timing track, lyric cues, environment hints. The engine loads it; adding a song never means rebuilding a scene. The definitions are structurally validated, and the lyric-sync engine is a pure function of time, so it can be tested deterministically outside the headset.

A real state machine for performance

Lobby, SongSelect, Countdown, Performing, Paused, Results: those are the exact state names in the code, with guarded transitions between them. It is the same discipline as backend work, applied to a play session. Interrupted playback is a handled case, not a surprise.

The audio is the truth

The playback clock advances from an injected time source, but each frame the manager compares it against the audio source's actual position. Drift past 0.15 seconds snaps the clock to the audio and counts the correction. Encoder delay and device latency get absorbed by the same mechanism.

Only licensed test content

Development uses original and public-domain material. No copyrighted recordings or lyrics ship with the project. Pitch scoring exists only as an honest seam: an interface, a null implementation, and no claims.

Testing and evidence

  • 30 NUnit tests pass headlessly outside Unity: song validation, the lyric-sync engine, the playback clock, and the performance state machine.
  • The Unity-side code is written carefully against the Unity 6 API but has not been compiled in an editor yet. It is labeled unverified until it is.
  • In-headset verification on Quest 3 is part of the development loop for interaction and comfort.

Results

  • Timing core, lyric sync, and state machine verified: 30 of 30 tests, run outside the headset.
  • Adding a song means writing a definition file, never rebuilding a scene.

Honest limitations

  • In active development. The tested core is real; the in-headset performance loop is still being built.
  • No public gameplay footage exists yet. Anything visual on this page that is not a diagram is labeled as illustrative.
  • Pitch detection and vocal scoring are not built and not claimed.

Status: In active development. The repository’s STATUS file tracks what is verified versus pending, in the open.
